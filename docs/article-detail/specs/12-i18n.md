# Spec 12 — i18n

Design ref: [../16-i18n.md](../16-i18n.md).

Add four key groups — `detail`, `share`, `comments`, `sidebar` — to the existing
`articles` namespace (en/fr). They live in a **new `article-detail.ts` locale file per
locale** that is spread into the existing locale barrel next to the `articles` bundle, so
keys resolve as `t("articles.detail.*")`, `t("articles.share.*")`,
`t("articles.comments.*")`, and `t("articles.sidebar.*")`. One file per usage area, no new
resource wiring — the `articles` namespace is already registered.

> **Read time is not redefined here.** The detail page reuses the feed's
> `articles.card.readTime` (`"{{count}} min read"`, already pluralized — see
> [../../articles/specs/07-i18n.md](../../articles/specs/07-i18n.md)); there is no
> `detail.readingTime` key.

## Registration

The detail keys are added by spreading the new `articleDetail` object into the existing
locale barrels, next to the already-spread `articles` bundle. Both barrels change
identically.

`src/modules/articles/presentation/i18n/locales/en/index.ts`:

```ts
import { articleDetail } from "@/modules/articles/presentation/i18n/locales/en/article-detail";
import { articles } from "@/modules/articles/presentation/i18n/locales/en/articles";
import { home } from "@/modules/articles/presentation/i18n/locales/en/home";

/**
 * en
 *
 * @description
 * English translation catalog for the articles module. Composes the module's namespaces:
 * the spread `articles` bundle (`card`, `grid`, `filters`), the spread `articleDetail`
 * bundle (`detail`, `share`, `comments`, `sidebar`), and the `home` namespace. The
 * composition root nests it under the `articles` key, so keys resolve as
 * `t("articles.card.read")` or `t("articles.detail.by", { name })`. Must stay key-aligned
 * with the French mirror.
 */
export const en = {
    ...articles,
    ...articleDetail,
    home
} as const;
```

`src/modules/articles/presentation/i18n/locales/fr/index.ts` (mirror):

```ts
import { articleDetail } from "@/modules/articles/presentation/i18n/locales/fr/article-detail";
import { articles } from "@/modules/articles/presentation/i18n/locales/fr/articles";
import { home } from "@/modules/articles/presentation/i18n/locales/fr/home";

/**
 * fr
 *
 * @description
 * French translation catalog for the articles module, mirror of the English barrel.
 * Composes the spread `articles` bundle, the spread `articleDetail` bundle
 * (`detail`, `share`, `comments`, `sidebar`), and the `home` namespace into a single
 * locale object the composition root nests under the `articles` key. Must stay key-aligned
 * with the English mirror.
 */
export const fr = {
    ...articles,
    ...articleDetail,
    home
} as const;
```

No change to `src/modules/articles/presentation/i18n/index.ts` or
`src/shared/presentation/i18n/resources.ts` — the `articles` namespace is already
registered; nesting new keys under it needs no resource wiring.

## Notes

- **Pluralization** — `comments.title` uses i18next plural suffixes (`title_one` /
  `title_other`); call as `t("articles.comments.title", { count })` for `"1 comment"` /
  `"12 comments"` (fr: `"1 commentaire"` / `"12 commentaires"`). Read time reuses the
  feed's already-pluralized `articles.card.readTime`.
- **Interpolation** — the byline is `t("articles.detail.by", { name })`; the name is data
  (`author.userName`), not i18n.
- **Brand names** — Facebook / X / WhatsApp are proper nouns; only the surrounding
  labels are translated. Copy-link's `copied` is the toast string (see
  [../08-share-rail.md](../08-share-rail.md)).
- **No literals in components** — every detail/share/comment/sidebar string above is
  referenced via `t(…)`. Category and tag names are data, not i18n.
- **Structural parity** — the en and fr `articleDetail` objects must hold the exact same
  keys, so a missing translation can't slip through.
