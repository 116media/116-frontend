# 16 — i18n

The detail page adds four key groups to the **existing `articles` namespace** (en/fr) —
`detail`, `share`, `comments`, and `sidebar`. No literal strings live in the detail
components: every label, toast, empty/error line, and aria/sr-only text is translated,
following the app's per-file locale convention. The authoritative key trees (full en + fr)
and the registration steps are in [specs/12-i18n.md](specs/12-i18n.md).

---

## Key groups

```
articles.detail.*     hero + engagement labels, "back to articles", the "By {{name}}" byline
articles.share.*      per-platform share labels + the copy-link toast
articles.comments.*   section title (pluralized), composer, empty/error, auth prompt, load-more
articles.sidebar.*    popular-articles heading + empty line
```

- **`articles.detail`** — `by` (`"By {{name}}"`), `share`, `like`, `bookmark`, `comment`,
  and `backToArticles`. There is **no** `detail.readingTime`: the read-time figure reuses
  the feed's **`articles.card.readTime`** (`{{count}} min read`, already pluralized — see
  [../articles/12-i18n.md](../articles/12-i18n.md)), so the detail page does not duplicate
  it.
- **`articles.share`** — `facebook`, `x`, `whatsapp`, `copyLink`, `copied` (the toast
  shown after copy-link), and `shareArticle` (the rail's group label / aria-label). Brand
  names (Facebook, X, WhatsApp) are proper nouns and stay identical across locales; only
  the surrounding labels differ. See [08-share-rail.md](08-share-rail.md).
- **`articles.comments`** — `title` uses i18next pluralization (`title_one` / `title_other`
  → `"{{count}} comment"` / `"{{count}} comments"`), plus `placeholder`, `submit`,
  `empty.title`, `empty.body`, `loginToComment`, `removed` (for a soft-deleted comment,
  `body: null`), `loadMore`, and `error`. See [12-comments.md](12-comments.md).
- **`articles.sidebar`** — `popular` (the "Popular articles" heading) and `empty`. See
  [11-popular-articles-sidebar.md](11-popular-articles-sidebar.md).

## Placement & registration

```
src/modules/articles/presentation/i18n/locales/en/article-detail.ts   (new)
src/modules/articles/presentation/i18n/locales/fr/article-detail.ts   (new)
```

The existing locale barrels
(`locales/en/index.ts`, `locales/fr/index.ts`) already **spread** the `articles` bundle
alongside the `home` namespace. The detail keys are added as a **sibling `article-detail`
file that is spread into the same barrel**, so the four new groups land at the top of the
`articles` namespace next to `card`/`grid`/`filters`:

```ts
export const en = {
    ...articles,
    ...articleDetail,
    home
} as const;
```

Keys therefore resolve as `t("articles.detail.by", { name })`,
`t("articles.share.copyLink")`, `t("articles.comments.title", { count })`, and
`t("articles.sidebar.popular")` — no new resource wiring is needed, since the `articles`
namespace is already registered in `src/shared/presentation/i18n/resources.ts`. The full
trees and the exact barrel edits are in [specs/12-i18n.md](specs/12-i18n.md).

## Notes

- **Pluralization** — `comments.title` uses i18next plural suffixes; call as
  `t("articles.comments.title", { count })` for `"1 comment"` / `"12 comments"` (and the
  French `"1 commentaire"` / `"12 commentaires"`). Read time reuses the feed's already-
  pluralized `card.readTime`.
- **Interpolation** — the byline is `t("articles.detail.by", { name })`; the author name
  comes from the data (`author.userName`), not i18n.
- **Data, not i18n** — category names (`categoryName`), tag names, and author usernames
  are DB-driven and never translated.
- **Structural parity** — the en and fr `article-detail` objects must hold the exact same
  keys, so a missing translation can't slip through; the spec's `## Tasks` checklist
  guards this.
